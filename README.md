# Programme Management Portfolio — Demo Artifact

A self-contained, worked example of how I run a programme end to end. It is built
around a **fictional but realistic** programme so it can be shared publicly without
touching any confidential employer data.

> **Author:** Viswanadham Ampolu
> **Purpose:** A capability demonstration for Programme Management roles — showing
> the artifacts I produce, the governance I apply, and how I keep a multi-workstream
> programme on track.

---

## The sample programme

**Orion — Customer Digital Onboarding Transformation**
Replace a slow, manual customer onboarding journey (10+ working days) with a
digital, compliant, self-serve journey (target: under 1 day) across four workstreams.

| | |
|---|---|
| **Duration** | 12 months (3 phases) |
| **Budget** | £2.4m |
| **Workstreams** | Product & UX · Platform Engineering · Risk & Compliance · Change & Adoption |
| **Governance** | Monthly Programme Board · fortnightly delivery review · weekly stand-ups |

The numbers, risks and dates are invented for the demo. The **structure, cadence and
artifacts** are exactly how I would run the real thing.

## How to read it

1. Start with the **[Charter](docs/charter.md)** for the "why".
2. Open **[index.html](index.html)** in a browser for the one-page dashboard.
3. Dive into the **[RAID log](docs/raid-log.md)** and **[Status report](docs/status-report.md)** —
   these are the two artifacts that show day-to-day control of a programme.

## Why a demo like this

Programme Management is hard to prove from a CV line. This repo is the evidence:
it shows that I can set up governance, make scope and risk explicit, communicate
status honestly (RAG with reasons, not just colours), and keep four workstreams
pulling in the same direction.

_All content is illustrative and created for demonstration purposes._
